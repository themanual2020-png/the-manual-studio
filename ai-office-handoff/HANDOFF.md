# ออฟฟิศทีม AI: เอกสารส่งต่อสำหรับย้ายเข้า Admin Panel

เอกสารนี้สรุปทุกอย่างที่สร้างไว้บน claude.ai เพื่อนำไปทำต่อใน Claude Code และฝังเป็นส่วนหนึ่งของ admin panel ของเว็บบริษัท

**วิธีใช้:** วางโฟลเดอร์นี้ไว้ในโปรเจกต์เว็บ แล้วคัดลอกข้อความในหัวข้อ "ข้อความเริ่มงานใน Claude Code" (ท้ายเอกสาร) ไปวางใน Claude Code

## 2. ระบบทำอะไรได้บ้าง

หน้าแรกเป็นแผนผังออฟฟิศ แต่ละห้องคือแผนก มีทีม AI 3 ตัวที่ส่งงานต่อกันเป็นขั้นๆ และมีบอร์ดงานด้านขวาที่ทุกคนในทีมเห็นร่วมกัน

| ห้อง | โหมดงาน | ทีม AI (ลำดับการส่งต่อ) |
|---|---|---|
| **Project Manager** | แตกงานโปรเจกต์ใหม่ · สรุปสถานะทั้งบริษัท · ตรวจงานจากทุกแผนก | น้องแตกงาน → พี่ตรวจ → พี่คุมงาน |
| **การตลาด** | วิเคราะห์ไฟล์แอด (Excel/CSV) · วางแผนหาลูกค้าใหม่ | พี่ตาราง → น้องเป้า → พี่กลยุทธ์ |
| **คอนเทนต์** | เขียนโพสต์/สคริปต์คลิป · แผนคอนเทนต์ทั้งเดือน | น้องปิ๊ง → พี่เรื่อง → น้องคำ |
| **บัญชี-การเงิน** | อ่าน Statement (PDF) · อ่านสลิป/ใบเสร็จ (รูป) · สรุปรายงานเดือน + สมุดบัญชี | น้องสแกน → พี่เช็ก → พี่บัญ |
| **IT** | ตรวจหน้าเว็บ (จากโค้ด + ภาพหน้าจอ) · วิเคราะห์ปัญหา/Error · รายชื่อเว็บไซต์ | น้องเฝ้าเว็บ → พี่ปลอดภัย → พี่ดีบั๊ก |
| **ข้อมูลบริษัท** | ชื่อ ธุรกิจ สินค้า ลูกค้าเป้าหมาย โทนแบรนด์ (ทุก agent ใช้ข้อมูลนี้) | – |

ฟีเจอร์ร่วม:
- ทุกการ์ดงานที่เสร็จแล้วมีปุ่ม "ให้ PM ตรวจงานนี้" ผลตรวจ (ผ่าน/ควรแก้ + รายการปัญหา) แสดงใต้การ์ด
- ห้อง PM มี KPI (โปรเจกต์ที่ทำอยู่ งานค้าง เลยกำหนด งาน AI รอตรวจ), บอร์ดโปรเจกต์ (งานลูกค้า/ภายใน) ที่แก้สถานะ ผู้รับผิดชอบ และวันส่งได้ทันที
- สมุดบัญชีแก้หมวดย้อนหลังได้, จัดการรายชื่อหมวดได้เอง, ระบบจำหมวดที่ผู้ใช้แก้ไว้ใช้ครั้งหน้า, ดาวน์โหลด CSV

## 3. หลักการออกแบบที่ต้องคงไว้

สิ่งเหล่านี้คือเหตุผลที่ระบบเชื่อถือได้ อย่าตัดออกตอนย้ายระบบ

1. **ตัวเลขคำนวณด้วยโค้ด ไม่ให้ AI คิดเลข** ROAS, CPA, ยอดรวม, กำไรขาดทุน, ความคืบหน้าโปรเจกต์ คำนวณใน JS แล้วส่งให้ AI พร้อมคำสั่ง "ห้ามคำนวณใหม่" AI ทำหน้าที่อ่าน จับคู่คอลัมน์ และเขียนสรุปเท่านั้น
2. **คนยืนยันก่อนบันทึกบัญชีทุกครั้ง** ผลอ่านสลิปและ Statement แสดงเป็นร่าง แก้หมวดและเลือกรายการได้ก่อนกด "บันทึกลงบัญชี"
3. **ตรวจยอดคงเหลือต่อเนื่อง (balance chain)** ทุกบรรทัดของ Statement: `ยอดก่อนหน้า ± จำนวนเงิน = ยอดคงเหลือ` บรรทัดที่ไม่ต่อกันจะถูกไฮไลต์ (ข้อมูลจริงเดือน ก.ย. ผ่านครบ 33/33)
4. **กันรายการซ้ำ** เทียบวันที่ + ยอด + ประเภทกับสมุดบัญชีเดิม แล้วติ๊กออกให้อัตโนมัติ
5. **รหัส PDF ไม่ถูกเก็บ** ใช้เปิดไฟล์ในเบราว์เซอร์ครั้งเดียว
6. **ตรวจหน้าเว็บแบบ deterministic ก่อน** 18 จุด (title, meta description, viewport, h1, alt, canonical, OG, mixed content, ฟอร์ม http, noopener, generator, favicon, JSON-LD, ขนาด) ด้วย `DOMParser` แล้วค่อยให้ AI สรุป
7. **บันทึกขั้นตอนของ agent ทุกขั้น** (`steps[]`) เพื่อให้คนเห็นว่าใครทำอะไร และให้ PM ใช้ตรวจย้อนหลังได้

## 4. สิ่งที่ผูกกับ claude.ai และต้องเปลี่ยน

ต้นแบบรันบน claude.ai artifact และเรียกความสามารถผ่าน `window.claude.use(...)` ใน admin panel จริงต้องแทนที่ทั้งหมดดังนี้

| ในต้นแบบ | หน้าที่ | แทนด้วยใน admin panel |
|---|---|---|
| `claude.use("sample")` → `sample(prompt, {onText, images})` | เรียก Claude, stream ข้อความ, ส่งรูป | **Backend endpoint** (เช่น `POST /api/admin/ai`) เรียก Claude API (Messages API) แบบ streaming ฝั่งเซิร์ฟเวอร์ **API key ต้องอยู่ฝั่ง server เท่านั้น** ส่งรูปเป็น base64 image blocks |
| `sample.json(prompt)` | ขอผลเป็น JSON | endpoint เดียวกัน + parse JSON ฝั่ง server (หรือใช้ structured output / tool use เพื่อบังคับ schema) |
| `claude.use("db")` + `onSnapshot` | เก็บข้อมูลร่วม, อัปเดตสด | ฐานข้อมูลของเว็บ (เช่น Postgres/Supabase/Firestore) อัปเดตสดใช้ realtime ของ DB นั้น หรือ polling/SSE ก็พอ |
| `claude.use("user")` (`id`, `profiles`, `search`) | รู้ว่าใครใช้งาน, รายชื่อคนในทีม | ระบบล็อกอินของ admin panel + ตาราง users และ **สิทธิ์ตามบทบาท** (เช่น ห้องบัญชีเห็นเฉพาะ finance/owner) |
| `claude.use("downloads")` | ดาวน์โหลด CSV | ดาวน์โหลดไฟล์ตามปกติ |
| `localStorage` | ไม่ได้ใช้เก็บข้อมูลสำคัญ | – |
| CDN: `xlsx@0.18.5`, `pdf.js@3.11.174` | อ่าน Excel/CSV และ PDF ในเบราว์เซอร์ | ติดตั้งผ่าน npm แนะนำ **อ่าน Excel ด้วย SheetJS เวอร์ชันใหม่จาก cdn.sheetjs.com** (แพ็กเกจ `xlsx` บน npm ค้างที่ 0.18.5 ซึ่งมีช่องโหว่ที่รู้จัก) หรือย้ายไปอ่านฝั่ง server |

**ค่าใช้จ่าย:** ในต้นแบบ AI ใช้โควตา Claude ของคนที่กดส่งงาน เมื่อย้ายเข้า admin panel จะกลายเป็นค่า API ของบริษัท ควรมี rate limit ต่อผู้ใช้และบันทึกการใช้งาน

## 5. โครงสร้างข้อมูล (data model)

ทุก document มี `id`, `createdAt` (ms), `byId` (ผู้สร้าง ในต้นแบบเป็น id ของ claude.ai ซึ่งใช้ต่อไม่ได้ ตอนนำเข้าให้ผูกกับผู้ใช้ admin)

**`tasks`**: งานของทีม AI ทุกห้อง
```
dept: "pm"|"marketing"|"content"|"finance"|"it"
mode: string            // โหมดงาน เช่น "ads", "stmt", "plan", "page"
title: string
status: "running"|"done"|"error"
steps: [{agent, text}]  // agent id ดู DEPTS ในต้นแบบ
result: {kind, ...}     // kind: ads | md | report | slips | stmt | breakdown | audit
error?: string
review?: {verdict:"pass"|"fix", note, issues:[{level:"high"|"medium"|"low", text}], at, byId}
```
`result` แยกตาม kind:
- `ads`: `{md, hasRev, hasConv, rows:[{n,p,s,r,ro,c,cpa,f}], more}`
- `md`: `{md, copy?}`
- `report`: `{figures (markdown table), md}`
- `slips`: `{items:[{date,merchant,amount,kind,category,note,confidence,flags,dup,remembered}], saved, savedCount}`
- `stmt`: `{bank, account, items:[{date,desc,amount,kind,balance,category,flags,dup,remembered}], tin, tout, chain, chainOk, saved, savedCount}`
- `breakdown`: `{project:{name,type,client,due,brief}, summary, risks[], tasks:[{title,dept,due,priority,flags}], saved, projectId?}`
- `audit`: `{url, checks:[{level,area,text}], md, copy}`

**`ledger`**: สมุดบัญชี
```
date: "YYYY-MM-DD" (ค.ศ.)
kind: "income"|"expense"
amount: number (บวกเสมอ)
category: string
merchant: string       // รายละเอียด/คู่โอน
note: string           // เช่น "ธนาคารกสิกรไทย 9634"
source: "stmt"|"slips"|"manual"
```

**`projects`**: `{name, type:"client"|"internal", client, due, brief, status:"active"|"hold"|"done"}`

**`ptasks`**: งานในโปรเจกต์ `{projectId, title, status:"todo"|"doing"|"review"|"done", priority:"high"|"normal"|"low", due, owner}` โดย `owner` เป็น `"dept:<key>"` หรือ `"u:<userId>"` หรือ `""`

**`settings`** (document เดี่ยว):
- `brand`: `{name, business, products, audience, tone}`
- `categories`: `{exp:[...], inc:[...]}` (ถ้าไม่มี ใช้ `DEF_EXP`/`DEF_INC` ในต้นแบบ)
- `catmap`: `{map:{"<คำอธิบายที่ normalize แล้ว>": "<หมวด>"}}` ใช้ `descKey()` ในต้นแบบ normalize
- `sites`: `{list:[{id,name,url}]}`

**`itstatus/<siteId>`**: ผลตรวจเว็บอัตโนมัติ `{ok:boolean, checkedAt, summary, issues:[string]}` (ยังไม่มีงานที่เขียนข้อมูลนี้ ดูข้อ 7)

## 7. สิ่งที่ควรทำต่อเมื่ออยู่ใน admin panel

เรียงตามที่คุยกันไว้:

1. **ฝ่าย IT ดูแลเว็บจากโค้ดจริง:** เมื่อระบบอยู่ในโปรเจกต์เดียวกับเว็บแล้ว ไม่ต้องวาง view-source อีก ให้ตรวจทุกหน้าจาก build/route จริง รัน `npm audit` หาแพ็กเกจมีช่องโหว่ สแกนหา API key ที่หลุดในโค้ด และสรุป git log รายสัปดาห์
2. **ตรวจเว็บอัตโนมัติรายวัน:** cron job ฝั่ง server ดึงหน้าเว็บตาม `settings/sites` เช็ก status code, เวลาโหลด, วันหมดอายุ SSL แล้วเขียนลง `itstatus` (UI ในห้อง IT รองรับแล้ว)
3. **ห้องใหม่: ฝ่ายขายและลูกค้าสัมพันธ์ (CRM):** เป็นเจ้าของรายชื่อลูกค้าทั้งหมด
   - ขั้นการขาย: ลูกค้าใหม่ → ติดต่อแล้ว → เสนอราคา → ปิดได้/ไม่ได้ → ลูกค้าเก่า (ติดตามซื้อซ้ำ)
   - AI: รายชื่อที่ต้องติดตามวันนี้, ร่างข้อความ LINE/อีเมล, ร่างข้อเสนอขาย, นำเข้าจาก Excel/CSV
   - เชื่อมห้องอื่น: ลีดจากการตลาดเข้าห้องขาย, ขอใบเสนอราคาจากบัญชี, กด "ปิดการขายได้" แล้วสร้างโปรเจกต์ในห้อง PM อัตโนมัติ, ห้อง PM เห็นยอดที่กำลังเสนอขาย
   - ข้อมูลลูกค้าเป็นข้อมูลส่วนบุคคลตาม **PDPA** ต้องจำกัดสิทธิ์ให้เฉพาะฝ่ายขาย/ผู้บริหาร
4. **เชื่อม FlowAccount Open API:** บันทึกรายจ่ายที่ยืนยันแล้วเข้า FlowAccount และออกใบเสนอราคา/ใบแจ้งหนี้ (ต้องขอสิทธิ์ API ก่อน: developer_support@flowaccount.com, 02-026-8989)
5. **สิทธิ์ตามบทบาท + บันทึกการใช้งาน (audit log)** โดยเฉพาะห้องบัญชีและห้องขาย
6. ตอนนี้งานที่ค้างนานเกิน 20 นาทีจะขึ้นเป็น "งานค้าง" ใน admin panel ควรรันงาน AI เป็น background job ฝั่ง server แทน ปิดหน้าเว็บแล้วงานจะได้ไม่หาย

## 8. ข้อมูลที่ระบบจำไว้ (ตัวอย่างจาก catmap)

|---|---|
